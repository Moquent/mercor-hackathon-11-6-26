# 3-minute demo script

Before you start: `python3 -m rootproof serve` and open http://127.0.0.1:8080/ (the live console). Keep
`results/report.html` open in a second tab for the static numbers.

1. **(0:00) Problem.** "AI on-call agents write confident root-cause analyses. Reading one can't tell you if it's right, or whether the agent actually checked what it claims. RootProof replays the outage with the AI's fix applied, and checks every claim against the steps the agent really took."
2. **(0:20) Replay a saved investigation.** Pick `16-link-partition`, run 1, then **Replay saved run**. On the topology the system breaks at 14:01:50. The agent cursor moves service to service as the AI calls tools, and each card on the right shows the tool, the AI's reason and what it saw. "Notice it never probes the player-core → media-cache link."
3. **(1:00) Verification runs live.** The pipeline lights up: Jev extracts its actions, then the fix is replayed on five seeds (the curves drop to zero, so the fix works). Then the claims fill in one by one, and one turns red: "player-core → media-cache (failure)" is false. media-cache had 0% errors. The first-wrong-step callout points at s15, and the topology blinks the link it never checked: that probe would have shown 92% refused. "Right fix, wrong reasoning. Checking the fix alone would accept this."
4. **(1:40) Your own case.** Open the Case composer and type the judges' scenario (for example: "after a DNS migration, session-api resolves meta-index to a decommissioned IP; a meta-index deploy went out the same minute"). The AI drafts the case, the simulator runs it, and the ground truth is computed by replaying every action. Click **Investigate this case** and the agent debugs it live, followed by the same verification.
5. **(2:20) Benchmark live.** Benchmark tab, then **Benchmark**. All 63 saved investigations are re-verified in about 10 seconds: 529 of 542 claims verified, 10 false, 54 clean trails. Then the static report: 12 of 15 first answers accepted without tools, and real RCAEval data where the verifier agrees with the label 90% of the time on the fresh split.
6. **(2:45) Limits.** "The systems are simulated, so fixes can be replayed exactly. Real data can't be replayed, so on RCAEval we check claims only. One subject model. An optional instrumented order system produces real execution traces; its graph checks do not prove counterfactual causation."

Q&A: *Why simulate?* Testing a fix needs executable ground truth, and real outages can't be replayed. *Can the agent see the answer?* No: its tools read only telemetry up to the page time, and the verifier's truth comes from the simulator, not from the agent. *Is the verifier itself right?* It has a self-test (30 of 30 reference and trap answers, 4 of 4 hand-built traces), and two hand audits of the extraction step (313 of 315 and 418 of 420 decisions).
